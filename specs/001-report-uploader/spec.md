# Feature Specification: Excel/CSV 上传自动生成报表工具

**Feature Branch**: `001-report-uploader`

**Created**: 2026-09-24

**Status**: Draft

**Input**: User description: "帮我工具：用户上传excel文件或者csv文件自动生成报表，用户能上传文件，创建目录，拖动文件在不同的目录位置下生成报表，第一版先做简单一点，用户先预定好几个，不做登录，就用来验证核心功能是否跑通"

## Clarifications

### Session 2026-09-24

- Q: "用户先预定好几个"指的是预置用户身份还是预置报表模板？ → A: 预置若干报表模板
- Q: 不做登录时，用户的数据空间如何划分？ → A: 单一共享空间，无身份选择与数据隔离（v1 验证默认，替代原"预设用户"方案）
- Q: 预置哪些报表模板、如何选用？ → A: 内置 3 个模板（数据概览、分组汇总、TOP N 排行）；生成报表时先选 1 个模板，需要指定列的模板再选择对应列

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 上传数据文件并生成报表 (Priority: P1)

用户打开工具后（无需登录），选择一个目录，上传 Excel 或 CSV 文件到该目录，然后针对该文件选择一个内置报表模板触发生成，系统基于文件中的数据自动产出报表，用户可以查看并下载该报表。

**Why this priority**: 这是整个工具的核心价值——"上传文件 → 生成报表"跑通即证明核心概念可行，其他功能都围绕它展开。

**Independent Test**: 可独立验证：选择目录 → 上传一份含表格数据的 CSV/Excel → 生成报表 → 查看/下载报表内容，全程无需其他功能参与。

**Acceptance Scenarios**:

1. **Given** 当前为空目录，**When** 用户上传一份合法的 CSV 文件，**Then** 文件出现在该目录中且文件名、大小可见。
2. **Given** 目录中已有一份合法的 Excel 文件，**When** 用户选择"数据概览"模板并触发"生成报表"，**Then** 系统在合理时间内生成报表并展示。
3. **Given** 用户已生成某文件的报表，**When** 用户查看报表，**Then** 报表包含所选模板要求的内容（如行列数、字段名、数值统计）并可被下载。
4. **Given** 用户上传或选择了格式非法/无法解析的文件，**When** 系统尝试生成报表，**Then** 系统给出明确的失败提示且不产生残缺报表。

---

### User Story 2 - 创建目录并组织文件 (Priority: P2)

用户可以创建目录（根目录 + 子目录，共 2 层），把已上传的文件拖动到不同目录位置下，形成自己的文件组织结构，并在任意目录内上传文件、生成报表。

**Why this priority**: 目录与拖动是用户组织数据的方式；没有它工具仍可用（所有文件在根目录），但体验和"验证目录场景下生成报表"的目标不完整。

**Independent Test**: 可独立验证：创建目录 → 将文件拖入目录 → 在该目录内上传新文件并生成报表。

**Acceptance Scenarios**:

1. **Given** 用户在任意位置，**When** 用户创建一个新目录，**Then** 目录立即出现在列表中且可被重命名为唯一名称。
2. **Given** 目录中存在文件，**When** 用户把文件拖到另一个目录上并释放，**Then** 文件移动到目标目录且原目录中不再显示该文件。
3. **Given** 文件位于子目录中，**When** 用户在该子目录内生成报表，**Then** 报表与源文件关联并可在该目录上下文中查看。
4. **Given** 用户尝试创建与同级已有目录/文件重名的目录，**When** 提交创建，**Then** 系统拒绝并提示名称冲突。

---

### User Story 3 - 使用内置报表模板生成不同类型的报表 (Priority: P3)

系统内置 3 个报表模板（清单以 FR-014 为权威）：数据概览、分组汇总、TOP N 排行。用户对同一文件可以选择不同模板生成不同类型的报表；需要指定列的模板（分组汇总需选择分组列、TOP N 需选择排序列与前 N 名的 N 值）由用户在生成前选择。

**Why this priority**: 模板是"预置若干报表模板"这一原始诉求的落点；基础的数据概览在 P1 已覆盖，多模板选择扩展了验证面但非跑通核心流程的必要条件。

**Independent Test**: 可独立验证：对同一文件分别用 3 个模板生成报表，比较输出内容差异与正确性。

**Acceptance Scenarios**:

1. **Given** 系统已初始化，**When** 用户查看模板列表，**Then** 展示 3 个内置模板及其说明，无创建/编辑/删除入口。
2. **Given** 目录中有一份含分类列与数值列的文件，**When** 用户选择"分组汇总"并指定分组列，**Then** 生成按该列分组的汇总报表。
3. **Given** 目录中有一份数值列文件，**When** 用户选择"TOP N 排行"并指定排序列与 N，**Then** 生成按该数值列排序的前 N 行报表。
4. **Given** 用户选择"分组汇总"或"TOP N 排行"模板，**When** 未选择该模板要求的分组列/排序列，**Then** 系统提示需先选择列，不生成报表。
5. **Given** 同一文件已存在某模板的报表，**When** 用户再次用同一模板生成，**Then** 旧报表被覆盖（不保留历史版本）。

---

### Edge Cases

- 上传非 Excel/CSV 文件（如图片、PDF、.txt）：系统应拒绝或明确提示不支持的格式。
- 文件损坏、编码异常、空文件（0 行数据）、只有表头：生成报表时应给出可理解的结果或错误提示，不得崩溃。
- 同一目录下文件同名重复上传：v1 拒绝并提示名称冲突（409），不自动改名（已确定，见 Assumptions）。
- 拖动文件到其自身所在目录：视为无操作、无副作用；拖到已存在同名文件的目录：拒绝并提示名称冲突（409）。
- 超大文件导致生成报表超时/失败：超出大小/行数上限时由上传或生成前置校验直接提示（FR-012）；未超限但生成超过 10 秒时给出超时反馈（FR-013）。
- 目录层级过深或删除非空目录：v1 已定——创建超过 2 层的目录拒绝并提示；删除含文件/子目录的目录拒绝并提示先清空（已确定，见 FR-004 与 Assumptions）。
- 报表重复生成：同一文件同一模板再次生成时覆盖旧报表，不保留历史版本（已确定，见 Story 3）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 免登录可用，所有用户共用单一共享数据空间（v1 无身份与隔离机制）。
- **FR-002**: 系统 MUST 支持用户上传 `.xlsx` 与 `.csv` 文件到指定目录；v1 支持的格式**仅限** `.xlsx` 与 `.csv`，其余格式（含 `.xls`、`.xlsm` 等）一律按 FR-003 拒绝。
- **FR-003**: 系统 MUST 拒绝不支持的文件格式，并以用户可理解的提示告知原因。
- **FR-004**: 系统 MUST 支持用户创建目录；v1 目录固定为 2 层（根目录 + 子目录），创建更深层级时拒绝并提示，且同级名称不可重复。
- **FR-005**: 系统 MUST 支持用户通过拖拽把文件从一个目录移动到另一个目录。
- **FR-006**: 系统 MUST 支持用户对目录中的任意 Excel/CSV 文件触发"生成报表"，生成时 MUST 从 3 个内置模板中选择其一。
- **FR-007**: 报表 MUST 基于源文件数据与所选模板自动生成，且 MUST 包含：文件基本信息（名称、生成时间）与数据规模（总行数、总列数）；数据概览模板另含字段清单与数值列基础统计（最小值、最大值、平均值、空值数）；分组汇总模板输出各组行数与数值列聚合；TOP N 模板输出排序列前 N 行。
- **FR-008**: 系统 MUST 允许用户查看已生成的报表并将其下载为可离线打开的文件。
- **FR-009**: 文件、目录与报表 MUST 在用户关闭并重新打开工具后仍然保留（数据持久化）。
- **FR-010**: 系统 MUST 在单一共享空间内持久化全部目录、文件与报表数据，不提供按用户隔离的数据视图。
- **FR-011**: 文件解析失败、格式非法、文件为空等错误情形下，系统 MUST 给出明确错误信息且不产出不完整的报表。
- **FR-012**: 系统 MUST 限制单个上传文件的大小上限，超出时提示用户（具体上限见 Assumptions）。
- **FR-013**: 报表生成 MUST 在 10 秒内完成（1 万行以内文件，见 SC-002）；超过等待阈值时系统 MUST 给出超时/仍在处理的明确反馈，不得无响应。
- **FR-014**: 系统 MUST 内置 3 个报表模板：数据概览、分组汇总、TOP N 排行；模板为只读，用户不可创建、编辑或删除。（原编号 FR-001a）
- **FR-015**: "分组汇总"模板 MUST 要求用户选择一个分组列；"TOP N 排行"模板 MUST 要求选择排序数值列与 N（默认 10）；缺少必选项时 MUST 阻止生成并提示。（原编号 FR-006a）

*Out of scope for v1 (see Assumptions)*：登录/注册、多人协作、报表自定义模板编辑、定时任务、移动端适配。

### Key Entities

- **报表模板 (Report Template)**: 系统内置的只读模板定义，包含唯一编码、名称、说明与所需参数（是否需要分组列/排序列/N）；v1 固定 3 个，初始化时写入。
- **目录 (Directory)**: 用户创建的文件夹，具有名称与父级位置，支持层级结构；同一父级下名称唯一。
- **数据文件 (Data File)**: 用户上传的 Excel/CSV 文件，记录文件名、格式、大小、所属目录与上传时间。
- **报表 (Report)**: 由某个数据文件 + 某个模板生成的产物，记录来源文件、所用模板、参数、生成时间与统计内容；同一文件同一模板仅保留最新一份（覆盖）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从打开工具到完成"上传文件 → 选择模板 → 生成报表 → 查看报表"全流程，首次尝试可在 3 分钟内完成。
- **SC-002**: 对一份 1 万行以内的合法 CSV/Excel 文件，95% 的报表生成请求能在 10 秒内完成并展示结果。
- **SC-003**: 90% 的测试用户能在不看说明文档的情况下，独立完成创建目录、拖动文件、生成报表三项操作。
- **SC-004**: 对所有非法输入（错误格式、空文件、损坏文件、超大文件、模板必选列缺失），系统 100% 返回可理解的提示，0 次无响应或崩溃。
- **SC-005**: 100% 的报表内容与源文件数据一致（行列数、分组聚合值、TOP N 结果抽样核对无偏差）。
- **SC-006**: 数据在会话结束后 100% 保留；同一文件同一模板重复生成时，报表 100% 被覆盖更新且无重复记录。

## Assumptions

- **"用户先预定好几个"指**：系统预置报表模板而非用户身份（Clarifications Session 2026-09-24）；模板清单以 FR-014 为权威，本节不再重复。
- 因不做登录，v1 采用单一共享数据空间，不做权限控制与安全审计；工具按内网/本地单机验证用途设计。
- v1 报表只能从 FR-014 所列 3 个内置模板生成；用户不可自定义新模板或调整模板计算逻辑。
- 报表下载格式为 xlsx（plan.md / research.md 已确定，可离线打开）。
- 单文件大小上限默认 10 MB、单文件行数上限默认 10 万行，超出给出提示；为验证核心流程的合理默认值，可调整。
- 目录层级 v1 固定为 2 层（根目录 + 子目录），创建更深层目录时拒绝并提示；不支持无限嵌套。
- 同名文件重复上传 v1 采用"拒绝并提示"策略；同名报表重复生成 v1 采用"覆盖旧报表"策略。
- 删除非空目录 v1 要求先清空其中文件，或明确提示不可删除。
- 数据持久化保存于系统中，无保留期限限制（验证阶段不做过期清理）。
- 界面面向桌面浏览器的单机验证场景，移动端不在 v1 范围内。
- 项目 Constitution 仍为模板占位状态，暂无额外治理约束。
